CLIENT TIER (React + Vite)
----------------------------------------------------------------------------------------------------

File: /client/index.html
- Concepts & Standards: Single-Page Application (SPA) Host Document, HTML5 Semantic Boilerplate,
  Modern ES Module Import Host (`<script type="module" src="/src/main.jsx">`).
- Engineering Role: Entry HTML container and mount anchor (`<div id="root">`) for React DOM.

File: /client/package.json
- Concepts & Standards: Declarative Dependency Manifest, Semantic Versioning (SemVer), Lifecycle Script Hooks.
- Engineering Role: Manages React, React-DOM, and Vite bundler dependencies and execution scripts.

File: /client/vite.config.js
- Concepts & Standards: Hot Module Replacement (HMR), Modern ESM Build Optimization, Plugin Pipeline.
- Engineering Role: Configures Vite compiler and the official @vitejs/plugin-react fast-refresh engine.

File: /client/src/main.jsx
- Concepts & Standards: Application Bootstrap, React 18 Concurrent Root API (`createRoot`), Strict Mode.
- Engineering Role: Mounts the top-level `<App />` component directly into `#root`.

File: /client/src/App.jsx
- SOLID Principles:
  * Single Responsibility Principle (SRP): Coordinates top-level layout and orchestrates shared state.
- React Architecture & Design Patterns:
  * Mediator Pattern: Mediates communication between TaskForm and TaskList via lifted state.
  * State Lifting: Keeps `tasks`, `loading`, and `error` in common ancestor to broadcast to siblings.
  * Unidirectional Data Flow: Passes states down via props and actions up via callback functions (`onSaved`).
  * React Hooks: `useState` (stateful lifecycle) and `useEffect` (side-effect data fetching on mount).

File: /client/src/index.css
- Concepts & Standards: Design System Foundation, CSS Custom Properties (CSS Tokens: `--red`, `--grey`),
  Responsive Grid Layouts, Mobile-First Media Queries, Defensive CSS Box-Sizing (`box-sizing: border-box`).
- Engineering Role: Unified presentation layer defining typography, inputs, badges, and dual columns.

File: /client/src/services/api.js
- SOLID Principles:
  * Single Responsibility Principle (SRP): Solely responsible for external HTTP communication.
  * Dependency Inversion Principle (DIP): UI components depend on abstract service functions, not raw fetch.
  * DRY (Don't Repeat Yourself): Centralizes base URL, headers, JSON stringification, and error extraction.
- Design Patterns:
  * Service Layer Pattern / API Gateway Adapter Pattern: Abstracts network calls behind named functions.
  * Error Normalizer: Translates HTTP error responses into clean JavaScript exceptions.

File: /client/src/components/Message.jsx
- SOLID Principles:
  * Single Responsibility Principle (SRP): Purely renders contextual feedback notifications.
- React Architecture & Design Patterns:
  * Presentational / Dumb Component: Stateless, driven strictly by `{ type, text }` props.
  * Accessible RIA Role Modeling: Uses `role="alert"` and `role="status"` for screen readers.

File: /client/src/components/TaskForm.jsx
- SOLID Principles:
  * Single Responsibility Principle (SRP): Exclusively responsible for gathering, validating, and submitting tasks.
- React Architecture & Design Patterns:
  * Controlled Component Pattern: Input values bound directly to React `useState` hooks.
  * Optimistic UI & Defensive Interactivity: Disables submit button during active network requests.
  * Callback Inversion (`onSaved`): Triggers parent component refresh upon successful persistence.

File: /client/src/components/SignupForm.jsx
- SOLID Principles:
  * Single Responsibility Principle (SRP): Dedicated strictly to user registration credentials.
- React Architecture & Design Patterns:
  * Controlled Component Pattern: Manages `fullName`, `email`, and masked `password` state.
  * Client-Side Guard Validation: Checks non-blank constraints and minimum 8-character password length.
  * Sensitive Data State Purge: Resets password from client RAM upon successful backend registration.

File: /client/src/components/TaskList.jsx
- SOLID Principles:
  * Single Responsibility Principle (SRP): Dedicated strictly to rendering the collection of saved tasks.
- React Architecture & Design Patterns:
  * Pure Presentational Component: Consumes `tasks`, `loading`, and `error` purely via props.
  * Virtual DOM Reconciliation: Utilizes unique `key={task._id}` for efficient DOM reconciliation.
  * Dynamic Badge Variant Dispatch: Renders CSS class based on priority (`badge high`, `badge medium`, `badge low`).
  * Defensive Date Formatting: Converts ISO date strings to localized UTC date strings.

SERVER TIER (Java + Spring Boot + SQL Relational Database)
----------------------------------------------------------------------------------------------------

File: /server/pom.xml
- Concepts & Standards: Declarative Build Automation (Maven), Dependency Management, Parent POM Inheritance.
- Framework Components Declared:
  * `spring-boot-starter-web`: RESTful API dispatcher and embedded web container.
  * `spring-boot-starter-data-jpa`: Relational ORM mapping with Hibernate and Spring Data.
  * `spring-boot-starter-validation`: Jakarta Bean Validation (JSR-380).
  * `spring-security-crypto`: Enterprise cryptographic hashing algorithms (BCrypt).
  * `h2`, `postgresql`, `mysql-connector-j`: Relational SQL Database drivers.
  * `spring-boot-starter-test`: Testing ecosystem (JUnit 5, Mockito, AssertJ, MockMvc).

File: /server/src/main/resources/application.properties
- Concepts & Standards: Centralized Configuration, Infrastructure-as-Configuration.
- Framework Features:
  * Server Port Binding (`server.port=5000`).
  * Relational SQL DataSource Configuration (`spring.datasource.url=jdbc:h2:mem:taskflowdb`).
  * JPA / Hibernate Dialect Binding (`spring.jpa.database-platform=org.hibernate.dialect.H2Dialect`).
  * Schema Auto-Migration Strategy (`spring.jpa.hibernate.ddl-auto=update`).
  * Embedded SQL Web Inspector Console (`spring.h2.console.enabled=true`).

File: /server/src/test/resources/application-test.properties
- Concepts & Standards: Isolated Test Environment, Ephemeral In-Memory Database Sandbox.
- Framework Features:
  * `ddl-auto=create-drop`: Ensures clean database schema creation and teardown per test cycle.
  * `server.port=0`: Dynamic port allocation to avoid collision during parallel runs.

File: /server/src/main/java/com/taskflow/TaskFlowApplication.java
- Concepts & Standards: Microservice Bootstrap, Component Scanning, Auto-Configuration Engine.
- Framework Features:
  * `@SpringBootApplication`: Meta-annotation bundling `@Configuration`, `@EnableAutoConfiguration`,
    and `@ComponentScan`.

File: /server/src/main/java/com/taskflow/config/WebConfig.java
- SOLID Principles:
  * Open/Closed Principle (OCP): Extends Spring's WebMvcConfigurer without modifying framework internals.
- Framework Features:
  * Cross-Origin Resource Sharing (CORS): Configures CORS origins, methods, and credential handling.

File: /server/src/main/java/com/taskflow/config/SecurityConfig.java
- SOLID Principles:
  * Dependency Inversion Principle (DIP): Exposes `PasswordEncoder` abstraction rather than concrete class.
- Framework Features:
  * Spring IoC Container / `@Configuration` + `@Bean`: Registers `BCryptPasswordEncoder` bean with
    automatic 10-round salt generation.

File: /server/src/main/java/com/taskflow/entity/Task.java
- Concepts & Standards: Object-Relational Mapping (ORM), Domain Model Encapsulation, SQL Table Schema.
- Framework Features:
  * Jakarta Persistence Annotations: `@Entity`, `@Table(name = "tasks")`, `@Id`, `@GeneratedValue`.
  * Database Constraints: Nullability checks, TEXT column definitions.
  * JPA Entity Lifecycle Interceptors: `@PrePersist` and `@PreUpdate` for automated UTC audit timestamps.

File: /server/src/main/java/com/taskflow/entity/User.java
- Concepts & Standards: Domain Model Encapsulation, Identity & Credential Isolation.
- Framework Features:
  * Jakarta Persistence: `@Entity`, `@Table(name = "users")`.
  * SQL Relational Schema Uniqueness: `@Column(unique = true, nullable = false)`.
  * Security Best Practice: Never stores raw passwords; persists exclusively `passwordHash`.

File: /server/src/main/java/com/taskflow/repository/TaskRepository.java
- SOLID Principles:
  * Interface Segregation Principle (ISP): Exposes clean repository API without forcing unused methods.
  * Dependency Inversion Principle (DIP): Higher-level services depend on this interface.
- Design Patterns:
  * Repository Pattern: Abstracts raw SQL query strings and database transactions behind domain interfaces.
- Framework Features:
  * Spring Data JPA / Hibernate: Query Method Derivation (`findAllByOrderByCreatedAtDesc()`).

File: /server/src/main/java/com/taskflow/repository/UserRepository.java
- SOLID Principles:
  * Interface Segregation Principle (ISP) & Repository Pattern.
- Framework Features:
  * Derived Boolean Query Execution: `boolean existsByEmail(String email)`.
  * Derived Optional Query Execution: `Optional<User> findByEmail(String email)`.

File: /server/src/main/java/com/taskflow/dto/TaskRequest.java
- SOLID Principles:
  * Single Responsibility Principle (SRP): Dedicated exclusively to capturing and validating inbound task JSON.
- Framework Features:
  * Jakarta Bean Validation (JSR-380): `@NotBlank`, `@NotNull`, `@Pattern(regexp = "Low|Medium|High")`.
  * Jackson Date Formatting: `@JsonFormat(pattern = "yyyy-MM-dd")`.

File: /server/src/main/java/com/taskflow/dto/TaskResponse.java
- SOLID Principles:
  * Single Responsibility Principle (SRP): Dedicated exclusively to formatting outbound task JSON.
- Design Patterns:
  * Adapter Pattern / Projection: Adapts SQL relational Long ID into MongoDB-compatible String `_id`.
- Framework Features:
  * Jackson JSON Custom Property Binding: `@JsonProperty("_id")` alongside standard `id`.

File: /server/src/main/java/com/taskflow/dto/SignupRequest.java
- SOLID Principles:
  * Single Responsibility Principle (SRP): Validates incoming registration requests.
- Framework Features:
  * Jakarta Bean Validation: `@NotBlank`, `@Email`, `@Size(min = 8)` enforcing password length policy.

File: /server/src/main/java/com/taskflow/dto/UserResponse.java
- SOLID Principles:
  * Information Hiding & Encapsulation: Prevents password hashes from ever leaving the backend boundary.
- Design Patterns:
  * DTO Projection: Exposes only safe fields (`id`, `_id`, `fullName`, `email`, `createdAt`).

File: /server/src/main/java/com/taskflow/service/TaskService.java
- SOLID Principles:
  * Single Responsibility Principle (SRP): Houses task business logic, trimming, and entity conversion.
  * Dependency Inversion Principle (DIP): Injected with TaskRepository via constructor injection.
- Design Patterns:
  * Service Layer Pattern: Encapsulates domain logic between controller and repository.
- Framework Features:
  * Declarative Transaction Management: `@Transactional(readOnly = true)` and `@Transactional`.

File: /server/src/main/java/com/taskflow/service/UserService.java
- SOLID Principles:
  * Single Responsibility Principle (SRP): Coordinates user registration, uniqueness checks, and hashing.
  * Dependency Inversion Principle (DIP): Injected with UserRepository and PasswordEncoder interface.
- Design Patterns & Security:
  * Password Hashing via BCrypt: Hashes plaintext passwords before persistence.
  * Duplicate Email Guard: Checks database index before insert and throws ConflictException.

File: /server/src/main/java/com/taskflow/controller/TaskController.java
- SOLID Principles:
  * Single Responsibility Principle (SRP): Handles HTTP routing, status codes, and request dispatching for tasks.
  * Dependency Inversion Principle (DIP): Injected with TaskService via constructor injection.
- Design Patterns:
  * Front Controller / REST Controller Pattern.
- Framework Features:
  * `@RestController`, `@RequestMapping("/api/tasks")`, `@GetMapping`, `@PostMapping`.
  * Automatic Inbound Validation Trigger: `@Valid @RequestBody`.
  * HTTP Semantic Response Formulation: Returns `200 OK` and `201 CREATED`.

File: /server/src/main/java/com/taskflow/controller/SignupController.java
- SOLID Principles:
  * Single Responsibility Principle (SRP): Handles HTTP routing and dispatching for user signup.
- Framework Features:
  * `@RestController`, `@RequestMapping("/api/signup")`, `@PostMapping`.
  * Inbound Validation & 201 Created Response.

File: /server/src/main/java/com/taskflow/exception/GlobalExceptionHandler.java
- SOLID Principles:
  * Single Responsibility Principle (SRP): Centralizes all application exception translation.
  * Open/Closed Principle (OCP): New exceptions can be mapped without modifying existing controllers.
- Design Patterns:
  * Interceptor / Aspect-Oriented Programming (AOP): Intercepts exceptions thrown across all controllers.
- Framework Features:
  * `@RestControllerAdvice`, `@ExceptionHandler`.
  * MethodArgumentNotValidException: Formats validation failures into clean `{ "message": "..." }` JSON.
  * Custom Exception Mapping: Maps `BadRequestException` to HTTP 400 and `ConflictException` to HTTP 409.

File: /server/src/main/java/com/taskflow/exception/ErrorResponse.java
- Concepts & Standards: Consistent Error Payload Contract.
- Engineering Role: Standardizes error JSON fields (`message`, `status`, `timestamp`) for client consumption.

File: /server/src/main/java/com/taskflow/exception/BadRequestException.java
- Concepts & Standards: Unchecked Domain Exception (HTTP 400 Bad Request).

File: /server/src/main/java/com/taskflow/exception/ConflictException.java
- Concepts & Standards: Unchecked Domain Exception (HTTP 409 Resource Conflict).

File: /server/README.md
- Concepts & Standards: Technical Documentation, Runbook, SQL Database switching instructions.
