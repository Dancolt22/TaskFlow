A complete step-by-step roadmap for building full-stack web applications 
(React, Node.js/Express, MongoDB) from scratch in the right sequence.

## 1. HIGH-LEVEL GOLDEN SEQUENCE (THE 10-STEP ROADMAP)

When building a full-stack project, following the proper creation sequence saves 
hours of debugging and prevents rework.

   [Step 1] Project Architecture & Folder Scaffolding
       ↓
   [Step 2] Environment Configuration (.env, .gitignore)
       ↓
   [Step 3] Database Connection & Schemas (Mongoose / MongoDB)
       ↓
   [Step 4] Server & API Routes (Express, Controllers, Middleware)
       ↓
   [Step 5] Backend Verification (Postman, curl, or Thunder Client)
       ↓
   [Step 6] Frontend Foundation & Global Design System (index.css tokens)
       ↓
   [Step 7] Client API Service Layer (api.js centralized fetch wrapper)
       ↓
   [Step 8] UI Components (Structure -> State -> Styles -> Interactivity)
       ↓
   [Step 9] Main App Assembly & State Lifting (App.jsx)
       ↓
   [Step 10] UI Polish, Responsive Tweaks & Final Validation

* Why Backend-First?
  Building and verifying the backend first gives you working, testable endpoints. 
  When you later build your React components, you already know the exact JSON shape 
  your backend expects and returns.

## 2. MICRO WORKFLOW: THE CORRECT ORDER TO BUILD A REACT COMPONENT

When building any individual React component (e.g. TaskForm, SignupForm, TaskList),
always follow this 5-stage order:

STAGE 1: STRUCTURE (Raw HTML / JSX Skeleton)
  - Write plain semantic HTML tags first (<form>, <label>, <input>, <button>).
  - Do not add state or CSS styling yet.
  - Goal: Ensure all needed elements, form fields, and labels are logically present.

STAGE 2: CONTROLLED STATE (useState & Inputs)
  - Declare state variables for your inputs:
      const [title, setTitle] = useState("");
  - Bind values to inputs: value={title}
  - Bind onChange listeners: onChange={(e) => setTitle(e.target.value)}
  - Verify in React DevTools or with console.log that typing updates state.

STAGE 3: STYLING & LAYOUT (CSS)
  - Add className attributes (e.g. className="card", "row").
  - Define styles in CSS (padding, colors, borders, grid/flexbox layout).
  - Style interactive states: :hover, :focus, :focus-visible, and :disabled.
  - Goal: Make the component visually clear, accessible, and responsive.

STAGE 4: LOGIC & FORM SUBMISSION (Handlers & API)
  - Create handleSubmit(e) with e.preventDefault().
  - Add client-side validation (check required fields, character limits).
  - Call your API service function (e.g. await createTask(...)).
  - Reset form inputs back to blank upon successful submission.

STAGE 5: USER FEEDBACK & EDGE CASES
  - Add loading state (e.g., const [saving, setSaving] = useState(false)).
  - Disable the submit button during submission to prevent duplicate records.
  - Show user-friendly error banners and success confirmation alerts.

## 3. STEP-BY-STEP WALKTHROUGH

### PHASE 1: PROJECT SETUP & ENVIRONMENT
1. Initialize project folders:
   - Root directory: taskflow/
   - Backend folder: server/
   - Frontend folder: client/
2. Initialize server:
   - Run: npm init -y inside server/
   - Install dependencies: express, mongoose, dotenv, cors, bcryptjs
3. Initialize client:
   - Run: npm create vite@latest client -- --template react
   - Install dependencies: react, react-dom
4. Create environment templates:
   - Create .env.example with placeholders (MONGODB_URI, PORT, CLIENT_ORIGIN).
   - Create local .env file with real credentials.
   - Add .env and node_modules to .gitignore to protect secrets.

### PHASE 2: DATABASE & BACKEND MODELS
1. Database Connection (server/config/db.js):
   - Check if process.env.MONGODB_URI exists (fail fast if missing).
   - Connect using mongoose.connect().
2. Data Modeling (server/models/):
   - Task.js: Define fields (title, description, priority, dueDate, timestamps).
   - Signup.js: Define fields (fullName, email, passwordHash, timestamps).
   - Add constraints: required, trim, lowercase, enum, maxlength.

### PHASE 3: BACKEND API ENDPOINTS & BUSINESS LOGIC
1. Routes (server/routes/):
   - routes/tasks.js:
     * POST /api/tasks: Validate incoming body, create task, return 201.
     * GET /api/tasks: Find all tasks, sort newest first (-createdAt), return 200.
   - routes/signup.js:
     * POST /api/signup: Validate email format & password length, check for duplicates,
       hash password with bcrypt (10 rounds), save record, return safe user object (no hash).
2. Server Entry Point (server/server.js):
   - Load .env.
   - Attach cors() and express.json() middleware.
   - Mount routes: app.use("/api/tasks", ...) and app.use("/api/signup", ...).
   - Add 404 JSON fallback handler.
   - Call connectDB() then app.listen(port).

### PHASE 4: BACKEND TESTING & VERIFICATION
Before writing frontend code, ALWAYS test your API:
1. Start server: npm run dev
2. Test POST /api/tasks with valid and invalid JSON.
3. Test GET /api/tasks to confirm data returns in expected array format.
4. Test POST /api/signup to ensure passwords are saved hashed in MongoDB.
5. Check MongoDB Atlas dashboard to confirm collections and documents exist.

### PHASE 5: FRONTEND SCAFFOLDING & DESIGN FOUNDATION
1. Clean up default Vite boilerplate in client/src.
2. Build Design System Foundation in client/src/index.css:
   - CSS variables (:root colors: --red, --red-dark, --white, --grey, --border).
   - CSS Reset: * { box-sizing: border-box; } body { margin: 0; }
   - Typography, base input styles, buttons, cards.
   - Layout grids (.layout for 2 columns, .column for stacked forms).
   - Mobile responsive media queries (@media (max-width: 760px)).

### PHASE 6: FRONTEND API SERVICE LAYER
Create client/src/services/api.js:
- Define API_URL using import.meta.env.VITE_API_URL || "http://localhost:5000".
- Create reusable request(path, options) helper with error handling.
- Create postJson(path, body) helper.
- Export clean functions: getTasks(), createTask(), createSignup().
- Why now? This shields all upcoming components from low-level fetch details.

### PHASE 7: BUILD INDIVIDUAL UI COMPONENTS
Build components one at a time in client/src/components/:

1. Message.jsx (Small, Reusable Foundation):
   - Renders success/error feedback banner.
   - Uses role="alert" or role="status" for accessibility.
   - Returns null if text is empty.

2. TaskForm.jsx (Controlled Form):
   - Step A: JSX structure (inputs, textarea, select, labels, submit button).
   - Step B: useState hooks for title, description, priority, dueDate.
   - Step C: Styling with .card, .row, input:focus outlines.
   - Step D: handleSubmit with client-side validation and createTask() call.
   - Step E: Add saving indicator, disabled button state, success/error feedback.
   - Step F: Accept onSaved prop to notify parent when new task is created.

3. SignupForm.jsx (User Registration Form):
   - Step A: JSX structure (fullName, email, password inputs).
   - Step B: useState hooks for inputs and status.
   - Step C: Password masking (type="password") and validation.
   - Step D: handleSubmit calling createSignup().
   - Step E: Clear sensitive password from state on successful submit.

4. TaskList.jsx (Display List):
   - Step A: JSX structure (<h2>, <ul>, <li>).
   - Step B: Props: { tasks, loading, error }.
   - Step C: Render loading state and error message.
   - Step D: Render empty state if tasks.length === 0.
   - Step E: Map tasks array with unique key={task._id}.
   - Step F: Style priority badges (.badge.high, .badge.medium, .badge.low).
   - Step G: Format UTC dates for accurate display.

### PHASE 8: COMPONENT ASSEMBLY & STATE LIFTING (App.jsx)
1. In client/src/App.jsx:
   - Declare shared state: [tasks, setTasks], [loading, setLoading], [error, setError].
   - Create loadTasks() function that calls getTasks() from api.js.
   - Add useEffect(() => { loadTasks(); }, []) to fetch data when the app loads.
2. Render Layout:
   - Header (<header className="header"><h1>TaskFlow</h1>...).
   - Left column: <TaskForm onSaved={loadTasks} /> and <SignupForm />.
   - Right column: <TaskList tasks={tasks} loading={loading} error={error} />.
3. Verify Component Interaction:
   - Adding a task in TaskForm triggers onSaved -> runs loadTasks -> TaskList updates!

### PHASE 9: USER EXPERIENCE, FEEDBACK & POLISH
1. Form resets: Verify forms clear their values after successful submission.
2. Duplicate submission protection: Verify buttons are disabled while saving.
3. Accessibility: Ensure every <label htmlFor="..."> matches an <input id="...">.
4. Error handling: Test what happens when the backend server is stopped.
   (The UI should cleanly display "Cannot reach the server").
5. Responsive layout: Check display on narrow mobile viewports.

### PHASE 10: FINAL END-TO-END TESTING & DEBUGGING
1. Start both servers concurrently:
   - Terminal 1: cd server && npm run dev
   - Terminal 2: cd client && npm run dev
2. Test happy paths:
   - Submit a task -> Confirm it appears immediately in the task list.
   - Register a user -> Confirm success message.
3. Test edge cases:
   - Submit empty fields -> Confirm validation error appears.
   - Submit password < 8 characters -> Confirm error appears.
   - Refresh browser page -> Confirm saved tasks persist from MongoDB.

## 4. COMMON PITFALLS TO AVOID

* Styling before creating the component skeleton:
  Trying to write CSS before knowing what HTML elements you need leads to
  wasted effort and broken layouts. Always write JSX first, style second.

* Calling fetch() directly inside component event handlers:
  Scattering fetch calls everywhere duplicates error handling and headers.
  Always create a centralized api.js service module first.

* Writing frontend code before backend endpoints exist:
  If you build forms before testing your API, you often have to rewrite
  payload fields when the backend contract differs from your assumptions.

* Forgetting the `key` prop in React lists:
  Always pass a unique identifier (such as `task._id`) to list items in `.map()`.
  Never use array indices if the list can be sorted or filtered.

* Storing plaintext passwords:
  Always hash passwords with bcrypt on the server before database insertion,
  and never return the password hash back in the API response.

Summary Motto:
"Structure First, State Second, Style Third, Connect Fourth, Polish Last."
